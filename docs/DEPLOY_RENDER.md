# EchoMiner — Card-free deployment (Render + Neon + Cloudflare)

For when no credit card is available. Everything below is on free plans that do
not ask for a card. The VM deployment in [`DEPLOYMENT.md`](DEPLOYMENT.md) is still
the long-term target (e.g. a JSS AHER institutional server); moving there later
takes about an hour and needs no code changes.

```
Visitor ─HTTPS─> Cloudflare (DNS) ─HTTPS─> Render free web service (Singapore)
                                           one process: website + API + extraction worker
                                                 │
                                                 └─> Neon Postgres (Singapore)
OTP / notices: Render ─HTTPS─> Brevo API ─> inbox   (sender noreply@echominer.in)
```

## What is different from the VM set-up

| | VM (`DEPLOYMENT.md`) | Render free (this guide) |
|---|---|---|
| Card needed | Oracle: yes | **No** |
| Sleeps when idle | No | **Yes** — after 15 min without visitors; next visit waits ~1 min |
| Memory | 12 GB | 512 MB (tested: 2,000 reports in one job peaked at ~240 MB) |
| Upload limit | 20 files / 200 MB | **5 files / 50 MB** per job |
| Email | Brevo SMTP | Brevo **HTTPS API** (Render free blocks SMTP ports) |
| Rate limiting | nginx | inside the app |
| Deploys | GitHub Actions over SSH | Render, automatically after CI passes |
| Database | Postgres on the VM | Neon free: 0.5 GB, scales to zero when idle |
| Data location | wherever the VM is | Singapore (Render + Neon) |

Uploaded PDFs and extracted rows are deleted after download, exactly as on the VM.

---

## Step 1 — Database: Neon (10 min)

1. https://neon.com → **Sign up** with GitHub or Google (no card).
2. Create a project: name `echominer`, Postgres version = the default,
   **region: AWS Asia Pacific (Singapore)**.
3. On the project dashboard click **Connect**. Turn **Connection pooling off**
   (use the direct connection) and copy the connection string. It looks like
   `postgresql://neondb_owner:••••@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require…`
4. Keep it private (password manager). You paste it into Render in Step 4.
   The app creates all tables itself on first start.

## Step 2 — Email: Brevo (20 min + verification)

1. https://www.brevo.com → sign up with `aiechominer@gmail.com` (free plan, 300 emails/day).
2. **Settings → Senders, Domains & Dedicated IPs → Domains → Add a domain** → `echominer.in`.
   Brevo lists DNS records (a `brevo-code` TXT, DKIM, DMARC). Add each one **exactly** in
   Cloudflare → `echominer.in` → **DNS → Records → Add record**, with **Proxy status: DNS only**
   (grey cloud) for any CNAME. Back in Brevo click **Authenticate** until all show verified.
   (Cloudflare must be **Active** first — it emails you.)
3. **Senders → Add a sender**: name `EchoMiner`, email `noreply@echominer.in`.
4. **Settings → SMTP & API → API Keys → Generate a new API key**, name `echominer-render`.
   Copy it (starts with `xkeysib-`); it is shown once.
5. **Authorised IPs:** Brevo blocks API calls from unknown IP addresses, and Render's
   outbound addresses are shared. Open https://app.brevo.com/security/authorised_ips and
   either **deactivate IP blocking**, or add the outbound IP addresses shown in Render
   (service → **Connect → Outbound**) after Step 4. If this is missed, registration fails
   and the Render log shows `brevo send failed: HTTP 401 … unrecognised IP address`.

## Step 3 — reCAPTCHA v3 (5 min)

https://www.google.com/recaptcha/admin/create → label `EchoMiner`, type **Score based (v3)**,
domains: `echominer.in` **and** your Render address `echominer.onrender.com` (or whatever
Render assigns — you can add it after Step 4). Copy the **site key** and the **secret key**.

## Step 4 — Render (15 min + first build ~10 min)

1. https://render.com → **Get Started** → sign up **with GitHub** (no card for free services).
   When asked, give Render access to the `surajsagan/ECHOMINER` repository.
2. Dashboard → **New → Blueprint** → pick `ECHOMINER`. Render reads `render.yaml` and shows
   one service, `echominer`, plan **Free**, region **Singapore**.
3. It asks for the values marked secret. Fill in:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string (Step 1) |
   | `BREVO_API_KEY` | the `xkeysib-…` key (Step 2) |
   | `RECAPTCHA_SECRET` | reCAPTCHA **secret** key |
   | `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` | reCAPTCHA **site** key |
   | `ADMIN_BOOTSTRAP_EMAIL` | the administrator's email, e.g. `aiechominer@gmail.com` |
   | `ADMIN_BOOTSTRAP_PASSWORD` | a long, unique password (16+ characters) |

   `SECRET_KEY` and `OTP_PEPPER` are generated by Render automatically.
4. **Apply**. The first build takes ~10 minutes (watch **Logs**). When it says
   `Application startup complete`, open the service's `https://echominer-xxxx.onrender.com`
   address — the site should load.
5. **Administrator authenticator (once):** in **Logs**, find the block
   `bootstrap-admin: created administrator …` and add the **setup key** to Google Authenticator
   or Microsoft Authenticator (*Add → Enter a setup key*). Then in **Environment**, **delete**
   `ADMIN_BOOTSTRAP_EMAIL` and `ADMIN_BOOTSTRAP_PASSWORD` and save. Sign in at `/admin` with
   the email, password and the 6-digit code.
   *If the log shows `an administrator already exists`, one was already created — this is expected on later starts.*

Deploys from now on are automatic: push to `main` → GitHub Actions CI → if green,
Render builds and deploys (`autoDeployTrigger: checksPass`).

## Step 5 — Domain: echominer.in → Render (10 min)

Cloudflare must show `echominer.in` as **Active** first.

1. Render → service → **Settings → Custom Domains → Add**: `echominer.in`, then again `www.echominer.in`.
2. Cloudflare → `echominer.in` → **DNS → Records → Add record** (replace `echominer-xxxx` with
   your Render address):

   | Type | Name | Target | Proxy status |
   |---|---|---|---|
   | CNAME | `@` | `echominer-xxxx.onrender.com` | **DNS only** (grey) |
   | CNAME | `www` | `echominer-xxxx.onrender.com` | **DNS only** (grey) |

   Delete any `AAAA` record for the domain (Render has no IPv6).
3. Cloudflare → **SSL/TLS → Overview → Configure → Full** (Render's guidance for Cloudflare).
4. Back in Render → Custom Domains → **Verify** each domain; wait until both show a
   certificate as issued (minutes).
5. Then switch both Cloudflare records to **Proxied** (orange cloud). This hides the service
   behind Cloudflare and gives the app the visitor's real IP for rate limiting.
6. Add `echominer.in` to the reCAPTCHA domains if not already there (Step 3).

## Step 6 — Launch checklist

- [ ] `https://echominer.in` loads (first load after idle can take ~1 min — normal on the free plan)
- [ ] Register with a real address → OTP email arrives (check spam once, mark "not spam")
- [ ] The three team addresses receive the registration notice
- [ ] OTP unlocks the tool on the same page; reload → still unlocked (trusted device)
- [ ] Another browser → **Already registered? Sign in** → code → unlocked
- [ ] Upload 1–5 real (authorised) PDFs → preview → **Download Excel** → 6 sheets, logos on the cover
- [ ] `/admin` sign-in with the authenticator code; publish one FAQ or news item
- [ ] GitHub Actions: latest CI run green; Render **Events** shows the deploy

## Operating it

- **Logs / restarts:** Render → service → **Logs**, **Manual Deploy → Deploy latest commit**.
- **Changing a setting:** Render → **Environment** → edit → **Save, rebuild and deploy**.
  `NEXT_PUBLIC_*` values are built into the pages, so they need the rebuild (Render does it).
- **Upload limits:** keep `MAX_FILES_PER_JOB` / `MAX_JOB_BYTES` and `NEXT_PUBLIC_MAX_FILES` /
  `NEXT_PUBLIC_MAX_UPLOAD_MB` in step (API limit and what the page tells users).
- **Backups:** Neon free keeps 6 hours of point-in-time history and allows 1 manual snapshot.
  Take a snapshot in the Neon console before any large change. The database holds researcher
  registrations and usage records only — report contents are deleted after download.
- **Free-plan limits to know:** Render gives 750 instance-hours a month (enough for one
  service); Neon allows 100 compute-hours a month and scales to zero after 5 idle minutes.
  New jobs wake the extraction worker instantly; while idle it checks the database only every
  15 minutes, so Neon can sleep. Even with an uptime monitor keeping Render awake, that is
  roughly 60 of the 100 free compute-hours — and normal academic use adds little.

## Moving to an institutional server later

1. Follow [`DEPLOYMENT.md`](DEPLOYMENT.md) from Phase 4 on the new Ubuntu VM.
2. Copy the data: `pg_dump "<Neon URL>" | psql …` into the VM's database (or start fresh).
3. In Cloudflare, point `echominer.in` at the VM (A record, proxied, SSL mode **Full (strict)**).
4. Suspend the Render service.

## Known limitations

| Item | Note |
|---|---|
| Cold start | ~1 min after 15 idle minutes. Optional: a free uptime monitor pinging `https://echominer.in/healthz` every 10 min keeps it awake (the health check does not touch the database). |
| 5 files / 50 MB per job | Memory headroom on 512 MB; raise gradually if needed and watch Render's memory graph. |
| Data leaves India | Render and Neon run in Singapore. Uploaded reports are processed there and deleted after download. |
| Direct `onrender.com` access | Bypasses Cloudflare; the app, reCAPTCHA and OTP still apply. |
| Parser defects (`docs/PARSER_AUDIT.md`) | Extractor runs unchanged by decision; 2 defects change record counts. |
